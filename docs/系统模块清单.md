# 泓泽宜通供应链管理系统（HongZe-SCMS）系统模块清单

> 文档版本：v1.1　编制日期：2026-11-15（v1.0 · 2026-11-13 初版）
> 适用系统：HongZe-SCMS 供应链管理系统（纯静态前端 + Node 静态服务器 + API 数据层对接 PostgreSQL；浏览器 localStorage 键为历史遗留）
> 本文档为系统全部代码模块的结构化清单，覆盖功能定位、数据结构、输入输出、核心接口与调用关系，是数据库设计、种子数据迁移与使用说明文档的基准依据。

## 1. 系统总体架构

### 1.1 技术形态

| 层次 | 说明 |
|---|---|
| 运行环境 | Node.js 原生静态服务器 `server.js`，监听 **8000 端口**，支持 clean URL（无后缀自动补 `.html`）与路径穿越防护 |
| 前端形态 | 无构建、无框架的纯 HTML/CSS/JS；脚本以 IIFE/UMD 形式全局挂载（`window.HZXxx`）；核心数据层为 UMD 双端导出（浏览器 + Node 单测） |
| 数据持久化 | **PostgreSQL（主存储）**：前端经 `common/hz-db.js`（HZDB 内存缓存基座）读写 `/api/*` 接口；localStorage 键空间前缀（`hz_*`、`hzwl_*`、`hz-scms-*`、`hz_flow_*`、`price`）为改造前历史遗留，客户旧键（hz_customers*）已于 2026-11-15 备份清理 |
| 种子机制 | 各数据层内置种子常量，首次加载写入并带版本号（`__version` / `SEED_VER`），版本变更自动重置 |
| 后端预留 | `HZData.use(name, adapter)` 与 `HZFlowData.use(name, {raw})` 统一适配器接口，供对接 PostgreSQL 后端 |
| 外部服务 | `/api/futures`（server.js 内置）：新浪财经公开期货接口代理（实时行情）；`vendor/leaflet`：矿山地图 |
| 数据库规划 | PostgreSQL 16（Docker 容器 `hongze-scms-db`，端口 5432，卷 `hongze-scms_pgdata`，库 `HongZe-SCMS`） |

## 3. 业务模块清单

## 3.1 首页（index）

- **功能定位**：门户聚合页，问候条 + KPI 数字卡（合同总金额/合同数量/在用矿山/在途航次等）+ 趋势图 + 最新动态 + 模块入口卡片。
- **类型**：数据调用展示型（只读，不写入）。
- **输入**：`hz_contracts`、`hz_mines`、`hz_ocean_voyages`、订单等各模块数据。
- **输出**：页面 KPI 与图表。
- **依赖**：被 index.html 引入；无其他模块依赖它。

## 3.2 客户管理（customers/）

- **页面**：`customers.html`（列表/审核/启停/编辑/归类）、`register.html`（公开注册，三类客户类型可选）。
- **类型**：数据录入编辑型（注册、审核状态机、编辑、类型归类）。
- **数据层**：`data.js` → `window.HZCustomerData`（UMD）；**持久化经 `common/hz-db.js` → `PUT/DELETE /api/customers` 落 PostgreSQL `customer.customer`（keepStale 合并写：只合并提交行、跳过 stale 清理，缺行提交不误删存量）**。
- **存储**：权威存储为数据库表 **customer.customer**（status 区分正式/待审核）。历史 localStorage 键说明：

| 历史键 | 原内容 | 现状 |
|---|---|---|
| hz_customers_v2 | 正式客户（含待归类存量主体） | 历史遗留键，已于 2026-11-15 全量备份后从浏览器清理；源代码已无读写 |
| hz_customers_pending_v2 | 待归类清单（旧迁移流程遗留；台账页启动时自动并入客户库并清空） | 同上 |

- **数据结构（客户实体）**：

| 字段 | 含义 | 示例 |
|---|---|---|
| id / name / name_key | 主键/名称/名称索引键 | |
| customer_type | 客户类型 | 集采贸易商/现货贸易商/下游客户 |
| contact / phone / credit_code | 联系人/电话/统一社会信用代码 | |
| source | 来源 | 平台代注册 / 自主注册 / 系统迁移（仅存量并入记录） |
| status | 状态 | 待审核/正常/停用/已驳回 |
| credentials[] | 资质凭证（现货贸易商必填） | |
| reject_reason / history[] | 驳回原因/审核历史 | |
| source_refs[] | 来源模块引用 | |
| created_at / updated_at | 审计字段 | |

- **状态机**：待审核→正常⇄停用；待审核→已驳回→重新提交→待审核。代注册（三类客户类型可选）保存即生效；公开注册需资质审核。无类型（待归类）客户不进入业务可引用名单，在编辑弹窗归类确认后生效。
- **核心接口**：`createByOperator / createSelfRegistered / reviewApprove / reviewReject / resubmit / updateInfo / setStatus / listActive / adoptPending / loadStore / saveStore / loadPending / savePending`。
- **输入**：代注册弹窗与公开注册页表单；历史遗留待归类清单（启动时自动并入，旧键已清理）。
- **输出**：正式客户库 **customer.customer**（经 `/api/customers`；已归类且状态正常的客户可被订单等业务模块引用）。
- **种子**：无内置种子（空启动）。

- **页面**：

| 页面 | 定位 |
|---|---|
| order-new.html | 新建订单（登录即建单，默认首屏）：第一步表单（登录主体/矿山/品类/吨价/目的地/智能方案/船舶 9 项） |

| order-port.html | 港口信息录入（拥挤度/效率/泊位） |
| order-capacity.html | 运力方案录入（汽运/铁路/联运通道） |
| order-plan.html | 运输方案录入（方案批次与中转详情） |
| order-detail.html | 订单详情（汇总展示、状态推进、财务/发运/动态节点） |

- **类型**：数据录入编辑型。
- **数据层 1**：`flow-data.js` → `window.HZFlowData`。
- **数据层 2**：`order-new-data.js` → `window.HZOrderNewData`（UMD 双端，可单测）。
- **9 张独立表（hz_flow_* 键空间，空启动）**：

| 键 | 表 |
|---|---|
| hz_flow_orders | 订单主表 |
| hz_flow_ports | 港口信息 |
| hz_flow_capacities | 运力通道 |
| hz_flow_plans | 运输方案批次 |
| hz_flow_channel_details | 公铁联运中转详情 |
| hz_flow_financials | 财务信息 |
| hz_flow_shippings | 通道发运信息 |
| hz_flow_milestones | 货物动态节点 |
| hz_flow_logs | 操作日志 |

- **9 态状态机 STATUS_META**：draft 录入中 → port 待港口 → capacity 待运力 → plan 待方案（create 阶段）→ pending_confirm 待确认 → confirmed 订单已确认 → shipping 发运中 → shipped 发运完成（business 阶段）→ completed 已完成（final 阶段）。

- **编号规则**：订单号 `HZ + yyyyMMdd + 4 位流水`；ID `前缀_时间戳36进制_随机`。
- **跨模块联动**：`upsertOrder` → ① `HZBusinessData.syncFlowOrder`（订单达"待确认"及之后自动同步订单台账）② `syncVoyageToOcean`（航运信息录入后自动生成海运航次）。删除订单级联清空 8 张关联表。
- **核心接口**：`init / createOrder / getOrder / listOrders / saveOrder / upsertOrder / deleteOrder / addOperationLog / use / genOrderId`。
- **order-new-data.js 关键常量**：`ROAD_TONS_PER_DAY=2500`（汽运吨/日）、`RAIL_TONS_PER_TRAIN=3500`（铁路吨/列，向上取整）、线路归属（曹庄镇站方向→曹庄镇线，其余→沧港线）、`RAIL_DIRECT_TAG='中矿试单已打通通道'`、`LEDGER_SYNC_STATUSES`（pending_confirm 起 5 态同步台账）。
- **内置种子**：`WHARF_SEED`（5 码头）、`MINE_SEED`（4 矿山×品类）、`PORT_SEED`（黄骅港）、`DEST_SEED`（3 站→堆场→钢厂三级目录）、`FALLBACK_SUBJECT`（泓泽宜通/平台运营部）。
- **核心接口**：`getLoginSubject/validateSubject`（E1 阻断）、`getDestCatalog/listStations/listYards/listSteels/resolveStationOfYard/listWharfOptions/listMineOptions/categoryOfMine/listPortOptions`、`evalDestination/validateDestination/validateTonnage/validatePrice/validateForm`、`computeSmartPlans`（智能方案）、`buildOrder/buildPortPrefill/buildCapacityPrefills/buildVesselInfoPatch/endNodeName/isLedgerSynced`。

## 4. 调用关系总图（文字版）

```
首页 index ──只读──> contracts / mines / ocean_voyages / orders

客户管理 customers ──引用──> 已归类且正常状态的客户（customers） ──> 订单/台账客户快照

订单台账 ──引用──> contracts / mines / ocean 航次 / trips 车次
订单向导 ──读取字典──> mine.main_products / dict(mineLoadPorts/dischargePorts) / ports / transfer / steel

执行跟踪 tracking ──聚合──> hz_orders + hz-scms-trips-v2 + hz_ocean_voyages
调度分析 dispatch ──只读──> hz-scms-trips-v2 + hz_warehouse_io_v1 + hz-scms-orders-v1 + hz_warehouse_suppliers_v1
合同看板 dashboard ──聚合──> hz_contracts + hz_orders

矿山管理 ──被引用──> 订单(向导/台账) / 海运航次 / 首页 KPI
海运管理 ──被引用──> 订单台账(voyage_id) / 执行跟踪
```
