## 1. 系统概述与架构

泓泽供应链管理系统（SCMS）面向铁矿石供应链业务，覆盖 **矿山 → 海运 → 港口 → 铁路 → 中转 → 仓储 → 车队 → 钢厂** 全链条资源管理与订单全生命周期跟踪。

```
┌─────────────────────────────────────────────────────────────────┐
│                        浏览器（纯前端，无框架）                     │
│  16 个业务模块页面（HTML/CSS/JS）+ 公共层（导航/单位换算/数据层）     │
└───────────────┬─────────────────────────────────┬───────────────┘
                │ localStorage 持久化（当前主存储）  │ HZData / HZFlowData
                ▼                                 ▼  后端适配器（预留）
┌───────────────────────────┐      ┌──────────────────────────────┐
│  server.js（Node 静态服务） │      │  PostgreSQL 16（Docker 容器）  │
│  监听 8000 端口 · clean URL │      │  库 HongZe-SCMS · 45 表        │
│  /api/futures 期货行情代理   │      │  5 个只读视图 · 只读账号        │
└───────────────────────────┘      └──────────────────────────────┘
```

**模块类型约定**（决定操作权限方向）：

| 类型 | 含义 | 涵盖模块 |
|---|---|---|
| **录入编辑类** | 支持新增/编辑/删除/状态流转 | 矿山、海运、铁路、中转、仓储、车队、钢厂（左侧菜单 1-9 中的 7 个物理维护模块）+ 客户、订单、合同、调度、价格指数上传 |
| **调用展示类** | 只读聚合展示，数据来自录入类模块 | 首页 KPI、订单跟踪、数据分析、合同看板、港口吞吐展示 |

## 2. 运行环境与启动步骤

### 2.1 环境要求

| 组件 | 要求 |
|---|---|
| Node.js | ≥ 18（原生 http 模块，无第三方依赖） |
| Docker Desktop | 用于 PostgreSQL 16 数据库（可选，当前版本业务数据以浏览器 localStorage 为主） |
| 浏览器 | Chrome / Edge 现代浏览器 |

### 2.2 启动步骤

```powershell
# ① 启动静态服务器（工作目录：项目根目录）
node server.js
# 输出：泓泽供应链管理系统已启动 → http://localhost:8000

# ② （可选）启动 PostgreSQL 数据库容器
docker start hongze-scms-db

# ③ 浏览器访问
# http://localhost:8000
```

> **说明**：`server.js` 支持 clean URL —— 访问 `http://localhost:8000/order-new` 自动映射到 `business/flow/order-new.html`。系统默认首页为 **新建订单页**（`business/flow/order-new.html`）。

### 2.3 数据库初始化（首次部署）

```powershell
# 应用全部数据库迁移（建库表结构）
node scripts/migrate.js up

# 导入演示种子数据
node scripts/seed.js up

# 校验导入结果（31 张表行数 + 外键完整性 + 视图连通性）
node scripts/verify-seeds.js
```

## 4. 快速上手：5 分钟走通新建订单

新建订单是系统业务主干的起点，一次提交将自动串联 5 个模块。

```
 新建订单页                       提交后自动联动
┌──────────────┐
│ ① 登录主体    │  自动填充
│ ② 货源信息    │  矿山(品类带出) + 港口 + 码头 + 船名 + 目的地级联
│ ③ 智能方案    │  公路/公铁联运/铁路直达 三方案自动计算
└──────┬───────┘
       │ 点击提交
       ▼
  1. 订单落库（状态：待港口，编号 HZyyyyMMddNNNN）
  2. 港口管理 —— 自动生成该订单的港口作业预填记录
  3. 运力管理 —— 3 条通道预填行（吨数/单价 0 待人工确认）
  4. 海运管理 —— 船名+货量齐备时自动生成航次（S-xxx，9 项船舶信息随单同步）
  5. 订单台账 —— 订单推进到「待确认」后同步进台账
```

**操作步骤**：

1. 左侧菜单点 **订单管理 → 新建订单**（默认首页即该页）。
2. 检查顶部登录主体横幅（绿色/蓝色为正常，红色为缺失需联系管理员）。
3. **货源信息**：搜索选择矿山（如「力拓」）→ 品类自动带出（只读）→ 选择接卸港（如「黄骅港」）→ 点选 1 个或多个码头 → 填写船名（如「远盛海 008」）。
4. **目的地**：站 → 库 → 钢厂 三级级联选择，路径条实时回显。
5. **智能方案**：货量 ≥ 某阈值时自动计算公路/公铁联运/铁路直达三种方案（含预估运费），缺参数时给出补齐提示。
6. **航运信息**：填写船公司/吨级/船型/航线/运行时间/海运单价/周期/发货方/收货方（9 项，将随单同步至海运航次）。
7. 点击 **提交订单**：成功浮层显示订单编号，可跳转「港口信息」或「订单详情」。

> ⚠️ 注意：**品类自动带出、不可手选**；吨位必须 > 0；船名留空则不生成海运航次。

## 5. 核心模块操作详解

### 5.1 客户管理

- **入口**：左侧菜单「客户管理」（客户台账 / 客户登记 / 客户同步）。
- **功能**：维护客户主数据（钢厂/贸易商等），与订单页「目的地-钢厂」联动。
- **操作**：客户登记页填写企业信息保存 → 台账列表查看/编辑；客户同步页处理统一客户池的迁移导入。
- **数据**：键 `hz_customers_v2`，空启动（首次由统一池迁移）。

### 5.2 订单管理（四步向导 + 状态机）

订单状态机共 **9 态**，单向推进（管理员可跳步）：

```
draft     →  port      →  capacity  →  plan      →  pending_confirm
(草稿)       (待港口)      (待运力)      (待方案)     (待确认)
                                                              │
completed ← shipped ← shipping ← confirmed ←──────────────────┘
(已完成)    (已发运)   (发运中)    (已确认)

台账同步点：pending_confirm 起的 5 个状态会自动同步至订单台账
```

- **四步向导**：新建订单 → 港口信息（order-port）→ 运力安排（order-capacity）→ 执行方案（order-plan），每步保存后进入下一环节。
- **状态流转**：详情页（order-detail）按角色流转；不允许回退；管理员可跳步。
- **数据**：键 `hz_flow_orders`（主干）等 9 键；订单编号当日流水递增。
- **删除订单**：级联清空港口/运力/航次关联数据，并通知台账移除。

### 5.3 价格指数管理

| 子页 | 类型 | 操作 |
|---|---|---|
| 汽运价格（truck） | 录入编辑 | 上传价格记录（含证据图片）、31 条演示数据 |
| 火运价格（rail） | 录入编辑 | 上传价格记录，16 条演示数据 |
| 铁矿石现货（iron-ore） | 静态展示 | 中矿国链港口现货快照（2026-05-25，20 条） |

**操作**：进入子页 → 点「上传数据」→ 填写日期/货种/起点/终点/单价/备注，可附证据图片 → 保存后列表刷新并进入最新指数卡片。

### 5.4 业务管理

- **总览（business）**：全局业务概览（调用展示）。
- **订单台账（orders）**：流程订单推进到「待确认」后自动入台账；支持人工补录、编辑状态（待确认/已确认/执行中/已发运/已完成/已终止）、关联车次与航次。9 条演示订单。
- **订单跟踪（tracking）**：按订单串联航次/车次的只读时间线展示。
- **结算管理（settlement）**：录入应收/应付结算单，关联订单与合同；8 条演示结算。

### 5.5 合同管理

- **合同台账（contracts）**：录入三方可贸易合同（甲方/乙方/丙方、金额、数量、执行进度）；5 份演示合同。
- **合同模板（templates）**：维护合同条款模板（含版本管理）。
- **合同看板（dashboard）**：签约/执行/回款聚合展示（调用展示）。

### 5.6 运输调度管理

- **调度看板（transport）**：12 条演示车次（公路/铁路双模式）按节点推进（港口→中转→钢厂）。
- **调度录入（transport-entry）**：录入车次，订单台账可关联车次号（`order_ledger_trip`）。

### 5.7 数据分析

- **分析页（analytics）**：建设中。
- **调度分析（dispatch）**：车次/通道维度的只读聚合分析。

### 5.8 矿山管理（1 号模块 · 录入编辑）

- **入口**：`/mine`。
- **功能**：5 家矿山主数据（力拓/必和必拓/淡水河谷/福斯特库/西芒杜），含产品目录（43 条）、价格基准（30 条）、合作伙伴（19 条）、矿山故事、地图定位（Leaflet）。
- **操作**：新增/编辑矿山卡片 → 完善产品规格（品名/年产量/品位/杂质/水分/应用）→ 维护价格基准与合作伙伴。矿山的「品类映射」会直接驱动订单页品类自动带出。
- **数据**：键 `hz_mines`。

### 5.9 海运管理（2 号模块 · 录入编辑 + 自动同步）★

详见 [第 6 章专项说明](#6-海运管理模块专项说明)。

### 5.10 港口管理（3 号模块）

- **功能**：2 家港口（黄骅港/青岛港），港区划（12 个）、集疏运通道（4 条）、吞吐展示页。
- **操作**：编辑港口概况/港区/通道；订单提交后自动生成「港口作业预填记录」（在订单四步向导第二步加工）。
- **数据**：键 `hz_ports_data`。

### 5.11 铁路供应商管理（5 号模块）

- **功能**：2 家铁路服务商（邯黄铁路等），服务事实、费用明细（含费率表）、联系人。
- **操作**：编辑供应商信息与费用表；铁路直达运力方案参考此价格。
- **数据**：键 `hz_railway_suppliers`。

### 5.12 中转站点管理（6 号模块）

- **功能**：3 个中转站（曹庄镇站/武安站/康城站），站点概况、 metrics、铁路线延长工程说明。
- **操作**：编辑站点信息；公铁联运方案的中转站点取自本模块。
- **数据**：键 `hz_transfer_stations`。

### 5.13 仓储管理（7 号模块 · 四个子页）

| 子页 | 功能 | 种子 |
|---|---|---|
| warehouse | 仓储供应商概览 | 2 家 |
| suppliers | 供应商明细 + 垛位管理（12 垛） | 同上 |
| io | 进销存台账 | 空启动 |
| customs | 海关监管台账 | 空启动 |

- **操作**：编辑供应商（吞吐/库容/面积/设施）；垛位绑定矿种与吨数（吨数格式如「2.5万吨」）；矿种下拉含 14 种铁矿石（PB粉/PB块/纽曼粉…）。
- **数据**：键 `hz_warehouse_suppliers_v1`、`hz_warehouse_ores_v1` 等 5 键。

### 5.14 汽运车队（8 号模块）

- **功能**：2 家车队（自营/合作/外协），运力规模、最低保障、最大运能。
- **操作**：编辑车队信息；公路方案运力引用车队名录。
- **数据**：键 `hzwl_fleets_v2`。

### 5.15 钢厂管理（9 号模块）

- **功能**：11 家钢厂（天铁集团/普阳钢铁/新兴铸管等），产能、矿石需求、注册资本、主营产品。
- **操作**：编辑钢厂档案；目的地级联的「钢厂」选项与客户库联动。
- **数据**：键 `hzwl_steels_v2`。

## 6. 海运管理模块专项说明

> **本模块是全系统唯一接收多来源自动同步数据的模块**，页面为「航次看板 + 港口现货 + COA 质检」三合一。

### 6.1 页面结构

```
┌─ 海运管理（/ocean）─────────────────────────────┐
│ ① 航次看板    6 个航次卡片（S-001 ~ S-006）        │
│    状态: 待装船/装船中/在途/已到港/已完成            │
│ ② 港口现货    20 条现货快照（Fe/SiO2/Al2O3/P/S…）  │
│ ③ COA 质检    1 份证书（810190245，含 14 项检验项）  │
└─────────────────────────────────────────────────┘
```

### 6.2 航次数据的三个来源（同步规则）

```
来源 A：订单流自动同步（主通道）
  新建订单提交 → 船名 + 货量齐备 → 自动生成航次（编号 S-001 递增）
  同步内容：船名/货种/货量(吨→万吨)/装货港/接卸港 + 船舶信息 9 项
  幂等键  ：flow_ref（订单 ID）—— 同一订单重复保存只更新不重复生成

来源 B：订单台账关联
  台账订单选择航次（voyage_id）→ 海运侧航次挂接业务单据

来源 C：手工录入
  海运页直接新增航次（无业务单据来源，用于自有航线）
```

### 6.3 同步规则明细（R1 / AC-O09）

| # | 规则 | 说明 |
|---|---|---|
| 1 | 触发条件 | 订单**船名已填** 且 **货量换算有效（> 0 吨）**，二者缺一不同步 |
| 2 | 航次编号 | `S-` + 三位流水（S-001、S-002…），自动递增 |
| 3 | 船舶信息 9 项 | 船公司 / 吨级 / 船型 / 航线 / 运行时间 / 海运单价 / 周期 / 发货方 / 收货方，整组随单同步 |
| 4 | 状态独立 | 航次初始状态「待装船」，后续推进由海运模块维护，不随订单状态机联动 |
| 5 | 幂等更新 | 同订单再次保存（如修改船公司）→ 更新既有航次，**不重复生成** |
| 6 | 单位换算 | 吨 → 万吨（如 70000 吨 = 17 万吨字段中的 7.0），换算非法不同步 |
| 7 | 级联删除 | 删除订单 → 自动清除其同步生成的航次 |
| 8 | 来源可溯 | 每条航次在数据库侧有同步映射记录（来源模块/来源单据/同步规则），见 `v_ocean_sync_view` |

### 6.4 数据库侧的同步映射

海运专用表 `ocean.ocean_voyage` + 同步映射表 `ocean.ocean_voyage_sync` 支持从其他业务模块的数据关联映射：

```sql
SELECT voyage_code, vessel_name, source_module, source_ref, sync_rule
FROM public.v_ocean_sync_view;

-- 演示种子输出（节选）：
-- S-001 | Pacific Glory  | order_ledger | HZ202608300001 | ledger_voyage_link
-- S-002 | Bulk Venture   | order_ledger | HZ202609140001 | ledger_voyage_link
-- S-006 | (手工录入演示航次) | manual       | (空)           | manual_entry
```

| sync_rule | 含义 | 数据来源 |
|---|---|---|
| `order_shipping_sync` | 订单航运信息同步 | 新建订单 vessel_info 9 项（浏览器侧 flow_ref 机制） |
| `ledger_voyage_link` | 台账挂接 | 订单台账 voyage_id 关联 |
| `manual_entry` | 手工录入 | 海运页直接新增 |

### 6.5 操作注意事项

- 手工删除/编辑自动同步的航次不会回写订单；订单侧重新提交会再次同步更新。
- 港口现货为外部数据快照（来源：中国矿产·中矿国链），日期 2026-05-25，仅展示不可编辑。
- COA 证书支持证书头 + 多检验项结构，导入时按「证书 1 条 + 检验项 14 条」落库。

## 7. 数据存储与持久化机制

### 7.1 当前主存储：浏览器 localStorage

| 键前缀 | 归属 | 示例键 |
|---|---|---|
| `hz_*` | 业务主数据 | hz_mines / hz_ports_data / hz_contracts / hz_orders |
| `hzwl_*` | 车队 / 钢厂 | hzwl_fleets_v2 / hzwl_steels_v2 |
| `hz-scms-*` | 调度车次 | hz-scms-trips-v2 |
| `hz_flow_*` | 订单流程 | hz_flow_orders / hz_flow_order_port / hz_flow_order_capacity |
| `price` | 价格指数 | hz_truck_price_index / hz_rail_price_index |

种子机制：各数据层内置种子常量 + 版本号（`__version` / `SEED_VER`），首次加载写入，版本变更自动重置。

### 7.2 模块类型与表结构设计差异（数据库侧）

| 维度 | 录入编辑类模块 | 调用展示类模块 |
|---|---|---|
| 物理表 | 建物理表 + 完整约束（NOT NULL / CHECK 枚举 / UNIQUE / FK） | **不建物理表**，仅建只读视图 |
| 写入路径 | 模块页面表单 → localStorage（当前）→ 预留 HZData 适配器 | 无写入，SELECT 视图 |
| 数据库对象 | mine_info / ocean_voyage / steel_mill 等 31 张种子表 | v_home_kpi / v_order_tracking / v_dispatch_analysis / v_contract_dashboard / v_ocean_sync_view |
| 权限 | 读写 | scms_reader 只读角色（NOLOGIN，供接入时授权） |

### 7.3 后端适配器（预留接口）

```js
// 业务数据层（16 个注册名统一挂接）
HZData.use('mines', { raw: () => fetch('/api/mines').then(r => r.json()) });

// 订单流程数据层
HZFlowData.use('orders', { raw: () => fetch('/api/flow-orders').then(r => r.json()) });
```

异常时自动回退 localStorage，`use(name, null)` 注销适配器。

## 9. 常见问题 FAQ

**Q1：页面数据清空了？**
localStorage 是浏览器本地存储，清除浏览器数据/无痕模式/换浏览器都会重置。刷新后种子数据自动恢复（含版本号校验）。数据库侧数据不受影响。

**Q2：新建订单品类下拉为空？**
矿山管理模块数据被清空（`hz_mines` 覆盖键被删）。到矿山管理页重新初始化，或清除 localStorage 后刷新由种子恢复。

**Q3：提交订单报「登录主体缺失」？**
登录体系未接入的降级保护。当前版本会自动以平台运营方主体填充；若出现红色横幅，请联系管理员检查登录配置。

**Q4：海运航次没自动生成？**
检查两点：① 船名是否已填；② 货量是否 > 0。任一缺失都不会同步（防脏数据）。

**Q5：数据库连接失败？**
确认容器运行：`docker ps` 查看 `hongze-scms-db`；未运行则 `docker start hongze-scms-db`。数据库名区分大小写，连接串需 `"HongZe-SCMS"`。

**Q6：迁移报「文件内容变更」？**
`meta.schema_migrations` 校验和保护检测到已应用版本的内容被修改。恢复原文件内容，或确认变更意图后联系运维重建版本（禁止直接改历史迁移）。

**Q7：种子重复导入会翻倍吗？**
不会。主表 ON CONFLICT 更新、从表 DELETE+INSERT，重复执行结果一致（幂等）。

## 10. 使用注意事项汇总

1. **品类自动带出**：订单页矿山品类由矿山管理模块映射生成，不可手动选择；映射缺失时提示联系运营维护。
2. **吨位校验**：订单货量必须为正数；0/负数/非数字均被拦截。
3. **状态不可回退**：订单状态机单向推进，仅管理员可跳步；删除订单会级联清理港口/运力/航次数据，不可撤销。
4. **台账同步时点**：订单推进到「待确认」才进入台账，之前的中间态不污染台账。
5. **海运现货只读**：港口现货为外部快照数据，不可编辑。
6. **数据库大小写**：库名 `HongZe-SCMS` 带连字符且区分大小写，SQL 中必须双引号包裹。
7. **禁止修改历史迁移文件**：校验和防护会拦截；新变更请新增 V00x 版本。
8. **浏览器兼容**：依赖现代浏览器 ES6+ 与 localStorage，不支持 IE。
9. **期货行情**：首页行情来自 `/api/futures` 新浪财经代理，公网不可用时页面降级显示。
10. **证据图片**：价格指数上传的证据图片存储于本地路径引用（`assets/seed/` 演示数据为占位路径）。
